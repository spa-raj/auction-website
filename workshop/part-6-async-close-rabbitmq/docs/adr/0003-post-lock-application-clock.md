# Use an injected application clock after acquiring the auction lock

The user chose an injected application clock for deterministic deadline tests, including advancing time while a request waits for its auction-row lock. Read that clock after acquiring the lock and reject at or after closing; HTTP arrival and transaction-start times do not determine eligibility. Related API time/status decisions and acceptance timestamps must agree with this clock. This replaces the copied database-clock authority with application-clock authority: normal operation uses real time, and multiple API instances require synchronized system clocks. Implemented in Slice 2 after user authorization. Auction posting retains its existing future-date validation; this clock governs bidding, catalog/detail ended status and API time responses.
